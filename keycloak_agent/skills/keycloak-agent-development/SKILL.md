# keycloak-agent development

This repository owns the Keycloak admin API facade, authentication boundary,
action-routed MCP tools, ontology and ingestion mappings, and packaged
connector content. Shared connector contracts, transports, TLS profiles, and
credential helpers belong to `scion-sdk`; admission, serving, and
durable graph state belong to their owning repositories. Read `AGENTS.md`
before changing code and keep credentials, private endpoints, realm data, and
customer records out of source, logs, fixtures, and skill content.

## Rapid delivery: the 5-minute contract

Specs are already designed. Deliver small, reviewable slices and cite the
owning spec row in the commit trailer.

- Find the owning row first with `git grep -n "<term>" -- specs` and extend
  the existing spec before adding requirement text.
- Reuse the one `Connector` in `keycloak_agent/__init__.py`, the `Api` facade
  in `keycloak_agent/api_client.py`, and the generated operation methods loaded
  by `keycloak_agent/api/api_client_base.py` from `keycloak_agent/api/openapi.json`. Do not
  create a second API, MCP, authentication, or transport plane.
- Preserve `KEYCLOAK_URL`, `KEYCLOAK_REALM`, `KEYCLOAK_TOKEN`,
  `KEYCLOAK_AGENT_USERNAME`, `KEYCLOAK_AGENT_PASSWORD`,
  `KEYCLOAK_CLIENT_ID`, `KEYCLOAK_CLIENT_SECRET`, and
  `KEYCLOAK_CLIENT_AUDIENCE` handling in `keycloak_agent/auth.py`. Use the SDK
  TLS resolver and client-credentials provider; never add a TLS-verification
  bypass or print credentials.
- Keep the registered tool modules in `keycloak_agent/mcp_server.py` and
  `keycloak_agent/mcp/` action-routed and aligned with the SDK dynamic surface.
  Preserve the source declarations in `keycloak_agent/connector_sources.py` and
  keep ingest mappings explicit and tenant-neutral.
  Mock Keycloak HTTP responses in local tests; never call a live realm or use
  live credentials in a gate.
- Every delivered requirement needs a bound focused test. Generated
  `specs/*/status.json` files come from the shared hooks; never hand-edit them.
- Keep `skills/**`, `ontology/**`, prompts, `mcp_config.json`, and connector
  source declarations coherent with the existing package-data and
  `keycloak-mcp` entry point. One logical change per commit, with the central
  criterion recorded using the repository's documented `Spec: none (<reason>)`
  form when no local requirements row exists, plus the assisting-agent trailer.

## Setup and gates

Use the pinned environment from `uv sync --locked`, then run the shared gates:

```bash
uv sync --locked
uvx pre-commit run --all-files
uvx pre-commit run --all-files --hook-stage pre-push
```

For focused feedback, run the smallest affected tests with the locked
environment, for example:

```bash
uv run --locked --extra test pytest -q tests/test_keycloak_development_skill.py
uv run --locked --extra test pytest -q tests/test_api_client.py tests/test_identity_realm_scoping.py
```

The canonical `.pre-commit-config.yaml` delegates `connector-standard`,
`secrets`, `spec`, `tests-fast`, and `dependency-readiness` to
`Knuckles-Team/pipelines` at `rev: main`. Do not copy those hooks locally or
bypass a failing check.

## Connector-specific checks

- Keep the multi-inheritance `Api` facade and OpenAPI-derived method naming
  stable when changing provider operations; add a focused mocked request test
  for a changed path.
- Preserve the SDK TLS profile, bearer/client-credentials refresh behavior, and
  the default `master` realm. Validate environment settings before provider
  calls and translate provider failures through the existing client boundary.
- Keep the `keycloak_agent/skills/`, `keycloak_agent/ontology/`,
  `keycloak_agent/connectors/`, prompts, and `mcp_config.json` files in package
  data. Keep ontology mappings and ingestion
  source metadata neutral and free of tenant-specific values.
- Documentation is published by `.github/workflows/pages.yml`, which calls
  `pages_pipeline.yml@main` with the checked-in spec dashboard config. Source
  status records live under `specs/` and are generated by the shared hooks.

## Packaging and publication

`pyproject.toml` declares `keycloak-mcp = "keycloak_agent:connector"` and
packages `skills/**`, `ontology/**`, `connectors/**`, prompts, and
`mcp_config.json`. For a genuine packaged-content release, keep the project
version, `CHANGELOG.md`, and the editable `keycloak-agent` entry in `uv.lock`
coherent, then inspect `uv build` output for
`keycloak_agent/skills/keycloak-agent-development/SKILL.md`.

The canonical release caller is `.github/workflows/pipeline.yml`: it publishes
the Python connector with `python_pipeline.yml@main`, then builds the rendered
connector container with `container_pipeline.yml@main` and
`render_connector: true`. Do not commit generated Docker artifacts or add a
second release publisher. Do not claim package, container, or Pages publication
from a local build; require the exact-source hosted evidence and public artifact.

## Delivery discipline

Work in a real Git worktree based on `origin/main`. Inspect the complete diff,
stage only reviewed paths, and verify `git status --short` after every gate.
Do not use `git stash`, `git add -A`, or `git add .`; preserve unrelated working
tree changes. Keep runtime, ontology, status, and generated artifacts outside
the bounded skill slice unless the owning requirement explicitly requires them.
